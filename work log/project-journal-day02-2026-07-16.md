## 2. 오늘의 의사결정 흐름 (시간순)

1. **Day 01 외부 검토 반영**: 120/121/122 장소 수 불일치가 더 복잡함을 재확인, SKT+KT 병용·50m 격자 비공개는 확인 완료로 정정, **서울시 자체 12시간 Seq2Seq 예측이 이미 존재**한다는 발견을 재확인.
2. **실행 로드맵 비판적 검토**: 본인이 제시한 15개 항목 구조(분석→요구사항정의/구현)에 **PoC 실행·검증 게이트가 통째로 빠져 있음**을 지적. Phase 1(분석)/Phase 2(PoC 실행·검증)/Phase 3(요구사항·구현) 3단계로 재설계.
3. **Phase 2 세부 실행 순서 설계**: 2-0(사전검증)~2-5(최종판정) 6단계, 조기 중단 조건 추가.
4. **프레시매니저 리서치 자료 검토**: 공유받은 리서치에서 **생존자 편향** 확인 — 확보된 사례가 전부 고성과·장기근속자.
5. **페르소나 확정**: 근거 있는 페르소나 2개(금융증권형/여의도, 관공서형/공덕) + 이론적 카테고리 3개, **성과 수준 축을 새로 제안**(리서치에 없던 것).
6. **Gate C 인터뷰 설계 확정**: 목적표집 4종(층화·최대변이·부정사례·이탈사례) 결합, 16명 표본, 이탈자·저성과자 모집 채널(블라인드·지역 커뮤니티) 별도 설계. 인용 논문(Palinkas et al., 2015) 원문 대조로 실재 확인.
7. **실명 후보 매칭 검증**: 서담비·설희정 매니저 관련 기사를 원문과 대조해 정확성 확인. 다만 **찾아낸 후보 전원이 고성과 사례**임을 재확인 — 생존자 편향이 검증 과정에서도 계속 재현됨.
8. **Gate C 생략 시도 2회 거부**: 본인이 "공개자료로 충분하다"고 제안했으나, 문서 자신의 결론("Gate C 통과 근거로 사용 금지")과 상충함을 근거로 두 차례 거부. 대신 어려움·이탈 경험자 2~3명이라도 실제로 인터뷰하는 절충안 제시.
9. **인터뷰 질문 재배열**: 행동(1~4)→실패사례(5~7)→솔루션(8~10) 순으로 보강, 핵심 검증 질문("사람 많아도 안 팔리는 곳")은 보충 질문 중에서도 필수로 격상.
10. **합성 인터뷰 시뮬레이션 수용**: 본인이 만든 "Gate C 합성 인터뷰 시뮬레이션" 문서는 스스로 "실제 인터뷰 아님"을 명시하고 있어 가설 검증용으로만 인정, 실제 Gate C 대체 불가 원칙은 유지.
11. **데이터 범위 확장 검토**: 실시간 상권현황(카드소비 대리변수)·날씨(예보/실측 분리)는 **필수 추가**로 반영. 대중교통·문화행사는 선택으로 격하. 15개 메타데이터 필드안과 6주 연장안은 1인 운영 규모에 과하다고 판단해 거부.
12. **요구사항 정의서 v0.4 최종 확인**: 외부 검토가 지적한 8건(버전 표기 잔존, FR 번호 순서, 문구 정밀화, 고유키 충돌, 일정 표현, 보관기간, 신규 FR 수용기준)과 Gate B 재정의를 파일과 직접 대조해 **이미 전부 반영돼 있음**을 확인 — v0.4를 확정본으로 승인.
13. **비개발자용 실행 가이드 작성**: 기술 용어를 뺀 5단계 절차(열쇠 받기→확인→자동화→점검→분석)로 재정리.
14. **API 키 발급 및 첫 호출**: 대괄호 표기 혼동으로 인증 오류 발생 → 정정 → 실제 데이터 수신 성공. **예측 필드명(FCST_TIME, FCST_CONGEST_LVL, FCST_PPLTN_MIN/MAX)과 여의도 장소코드(POI072)가 실API로 확인됨** — 이전까지 "확인 필요"였던 두 항목 해소.
15. **자동 수집 파이프라인 구축**: 구글 스프레드시트 3개 시트(raw_log/population_current/population_forecast) + Apps Script 코드, 5분 주기 트리거 설정. 트리거 등록 시 함수 미표시 문제는 "먼저 저장 후 1회 수동 실행" 순서로 해결.
16. **자동 수집 가동 확인**: 2026-07-16 20:32:36 첫 자동 기록이 세 시트 모두에 정상 저장됨을 확인.

## 8. 다음 세션 할 일 (우선순위 순)

1. **[최우선] 수집 스크립트에 상권현황(FR-7)·날씨(FR-6) 호출 추가** — 지금 추가하지 않으면 그 사이 기간의 상권·날씨 데이터는 과거로 되돌아가 수집할 수 없다(서울시 실시간 데이터는 과거 이력을 제공하지 않음, Day 01에서 이미 확인된 제약). 가장 시급함.
2. **Gate C 1순위 그룹(어려움 경험 5명 + 이탈 경험 3명) 모집 공고 실제 게시** — 블라인드·지역 커뮤니티 채널로 시작, 데이터 수집과 병행.
3. 며칠 후 `raw_log` 결측률과 데이터 지연(기준시각 vs 호출시각) 패턴을 확인해 32분 지연이 반복되는지 판단.
4. 1주차 종료 시점에 수집 안정화 여부만 확인(분석은 아직 하지 않음).
