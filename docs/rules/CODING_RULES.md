# Coding Rules

## 1. 문서 목적과 책임

이 문서는 Freshmanager 데이터 타당성 PoC의 코드 구조, 오류처리,
보안, 저장과 테스트 작성 규칙을 정의한다.

문서별 책임은 다음과 같이 분리한다.

- `AGENTS.md`: 제품 범위, 최상위 원칙과 PM 승인 범위
- `README.md`: 현재 상태와 비개발자용 안내
- `CODING_RULES.md`: 구현 방법과 코드 작성 규칙
- `PROJECT_GUARD_SPEC.md`: 검사 ID, 판정 상태와 종료 코드의 유일한 기준
- `QUALITY_GATES.md`: 엔지니어링 게이트 순서와 진입·통과 조건
- `PROJECT_GUARD_REPORT_TEMPLATE.md`: 실제 검사 결과 기록 형식

이 문서에서는 검사 ID를 정의하거나 품질 게이트를 새로 만들지 않는다.

---

## 2. 기본 개발 언어와 의존성

기본 개발 언어는 Python 3이다.

Python 실행 형식은 다음과 같다.

```bash
python3 파일경로
```

- 가능한 경우 Python 표준 라이브러리를 우선한다.
- 새로운 패키지나 라이브러리 설치는 PM 승인 후 진행한다.
- 공식 장소 CSV 처리·검증을 위해 `openpyxl`을 사용하거나 설치하지 않는다.
- `.env` 처리를 위해 `python-dotenv`를 사용하거나 설치하지 않는다.
- 구현되지 않은 파일의 실행 명령을 실행 가능한 사실처럼 문서화하지 않는다.

---

## 3. 구현 단위와 코드 구조

다음 책임을 분리된 함수 또는 모듈로 구현한다.

- 환경설정 읽기
- 공식 장소 CSV 읽기와 읽기 전용 검증
- API 요청 준비
- 원본 JSON 저장
- 응답 파싱과 분석용 변환
- 수집 메타데이터와 오류 로그 기록
- 배치 실행, 실패 격리와 결과 집계

한 번의 변경은 현재 엔지니어링 게이트에 필요한 최소 단위로 제한한다.
광범위한 예외처리로 오류를 숨기거나 요청받지 않은 리팩터링을 하지 않는다.

## 4. 장소 기준데이터 규칙

수집기와 Project Guard가 공통으로 사용하는 유일한 공식 장소 기준파일은 다음과 같다.

```text
data/reference/seoul_121_places.csv
```

현재 공식 CSV는 정비와 `main` 반영 및 읽기 전용 재검증을 완료해 EG-1을 통과했다.
XLSX 파일과 XLSX 보존 경로는 사용하지 않는다.

- 수집기와 Project Guard는 같은 공식 CSV만 장소 순회·코드 조회·검증 입력으로 사용한다.
- CSV는 `open(..., mode="r", encoding="utf-8-sig", newline="")`로 열고
  표준 라이브러리 `csv.DictReader`로 읽는다.
- `utf-8-sig`로 UTF-8과 UTF-8 BOM을 모두 처리하며 BOM 존재 자체를
  필수조건으로 요구하지 않는다.
- 헤더는 `CATEGORY`, `NO`, `AREA_CD`, `AREA_NM`, `ENG_NM`의 정확한
  5개 컬럼과 순서인지 검사한다.
- 헤더를 제외한 121행, `AREA_CD` 결측·중복 없음, `AREA_NM` 결측 없음,
  여의도 `POI072`, 분류별 합계 121을 검사한다.
- `POI001`부터 `POI121`까지 코드 생성, `NO`의 코드 전환과 자동 보정을 금지한다.
- 파일은 읽기 모드로만 열고 코드가 CSV를 쓰기·추가·정렬·보정·덮어쓰기·
  재인코딩하거나 다른 형식으로 변환하지 않는다.
- 검사 실패 시 CSV를 자동 수정하지 않고 FAIL로 판정해 PM에게 보고한다.

## 5. 최소 `.env` 로더 계약

프로젝트 루트의 `.env`에서 `SEOUL_OPEN_API_KEY`를 읽는 최소 로더는
다음 규칙을 따라야 한다. 이 로더는 아직 구현되지 않았다.

실제 `.env` 생성과 실제 인증키 저장은 EG-3 오프라인 Project Guard 통과 후
PM이 EG-4 진입과 여의도 1장소 실제 호출을 승인한 뒤에만 진행한다.
EG-3까지의 로더 검사는 임시 `.env` fixture와 가짜 키만 사용한다.

1. 각 줄의 앞뒤 공백을 제거한다.
2. 빈 줄과 `#`로 시작하는 주석 줄을 무시한다.
3. 유효한 줄을 최초 등호(`=`) 하나를 기준으로 키와 값으로 분리한다.
4. 키와 값의 앞뒤 공백을 제거한다.
5. `.env` 미존재, `SEOUL_OPEN_API_KEY` 미존재 또는 빈 값이면 API 요청 전에
   `config_error`로 처리한다.

- 실제 키를 콘솔, 로그, 오류 메시지 또는 테스트 결과에 출력하지 않는다.
- URL을 기록해야 하면 인증키 부분을 `********`로 마스킹한다.
- 테스트에서는 임시 파일과 가짜 키를 사용한다.
- 따옴표 해석, 변수 치환과 인라인 주석 제거 같은 추가 문법은 임의로 지원하지 않는다.

---

## 6. API 요청과 보안

- 실제 서울시 API 호출은 EG-3 오프라인 Project Guard 통과 후 PM이 EG-4 진입과
  여의도 1장소 호출을 승인한 별도 실행에서만 수행한다.
- 일반 Project Guard와 일반 테스트는 네트워크와 실제 서울시 API를 호출하지 않는다.
- API 키는 함수 인자 또는 설정 객체로 전달하고 전역 문자열로 복제하지 않는다.
- API 키가 포함된 전체 URL을 출력하거나 오류에 포함하지 않는다.
- 로그에는 실제 URL 대신 `citydata_ppltn` 같은 논리적 `endpoint_name`을 기록한다.
- URL 기록이 불가피하면 인증키를 `********`로 바꾼 값만 기록한다.

## 7. 원본·예측·날씨 저장

### 원본 JSON

- API 응답을 받은 그대로 새 파일에 저장한다.
- 기존 원본 파일을 덮어쓰거나 수정·삭제하지 않는다.
- 파일명에 공식 CSV의 장소코드와 요청시각을 포함한다.
- 이상값과 결측을 원본에서 삭제·보정하지 않고 별도 오류 로그에 기록한다.
- 원본 필드명과 문자열 형태의 숫자를 원본 파일에서 변환하지 않는다.

### 예측 스냅샷

- 요청시각, 예측 스냅샷 시각, 예측 대상시각과 후속 관측시각을 구분한다.
- 같은 예측 대상시각의 새 스냅샷이 와도 기존 예측을 덮어쓰지 않는다.
- 공식 발행시각 필드가 없으면 임의로 만들지 않는다.

### 날씨

- 관측값과 예보값을 분리 저장한다.
- 예보 발행시각과 예보 대상시각을 보존한다.
- 예보 결측을 사후 관측값으로 대체하지 않는다.

## 8. 최소 수집 메타데이터

수집 결과에는 다음 필드만 최소 계약으로 사용한다.

| 필드 | 규칙 |
|---|---|
| `request_id` | 요청을 구분하는 고유값 |
| `endpoint_name` | `citydata_ppltn` 같은 논리적 이름이며 실제 URL이 아님 |
| `requested_at` | API 요청시각 |
| `http_status` | 실제 HTTP 상태이며 응답 전 실패를 숫자 `0`으로 보정하지 않음 |
| `area_code` | 공식 CSV에서 읽은 `AREA_CD` |
| `collection_status` | 수집 처리 결과이며 설정 누락은 `config_error` |
| `raw_file_path` | 저장된 원본 JSON 경로이며 원본 내용이 아님 |
| `parser_version` | 사용한 파서 버전 |

기존 이름인 `endpoint`와 `raw_payload`를 사용하지 않는다.

## 9. 오류처리와 배치 실패 격리

- 설정, 파일, HTTP, JSON, 검증 오류를 구분해 기록한다.
- 오류에 실제 API 키나 비마스킹 URL을 넣지 않는다.
- 한 장소 실패를 기록한 뒤 다음 장소를 계속 처리한다.
- 재시도 횟수는 유한한 설정값으로 관리하고 무한 재시도를 금지한다.
- 회차 종료 후 대상·성공·실패 건수와 실패 장소 목록을 기록한다.
- 대상 건수는 성공 건수와 실패 건수의 합과 일치해야 한다.

---

## 10. 결측과 상권 상태

- `not_supported`: 해당 장소가 상권현황 지원대상이 아님
- `missing`: 지원대상이지만 해당 시점 데이터가 없음
- 숫자 `0`: 실제 응답에서 확인된 값

세 상태를 구분하고 `not_supported`나 `missing`을 `0` 또는 `한산`으로
변환하지 않는다. 상권현황은 카드소비 기반 소비활동 대리변수로만 표현한다.

---

## 11. 테스트 작성 규칙

- 일반 테스트는 저장된 샘플 JSON 또는 가짜 응답을 사용한다.
- 네트워크 소켓, HTTP 요청과 실제 서울시 API 호출을 금지한다.
- 실제 API 키를 테스트 코드, fixture와 예상값에 넣지 않는다.
- 파일 저장 검사는 임시 디렉터리를 사용하고 실제 원본을 변경하지 않는다.
- 성공 경로뿐 아니라 설정 누락, 결측, 실패 격리와 재시도 제한을 검사한다.
- PM 승인된 실제 호출은 일반 테스트와 별도 수동 실행으로 구분한다.

---

## 12. 변경과 검증 원칙

구현 전 현재 EG와 `PROJECT_GUARD_SPEC.md`의 적용 검사 ID를 확인한다.
적용 대상 필수검사를 통과한 뒤 결과를 보고하고, 다음 구현 단계 전환은
PM 승인 후 진행한다. 검사 실행 자체에는 PM 승인이 필요하지 않다.

다음 작업은 PM 승인을 받는다.

- 품질 게이트 통과 후 다음 구현 단계로의 전환
- 실제 서울시 API 호출
- 새로운 패키지 또는 라이브러리 설치
- 기준파일 생성·배치·교체·변경
- 데이터 저장구조 변경
- API 호출주기 결정 또는 변경
- 자동실행 구성 또는 변경
- GitHub main 브랜치 병합
